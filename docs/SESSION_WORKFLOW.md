# CausalGround — 단계별 세션 운영

Status: working process agreed from the user's request to split the research into stages. Research-hypothesis decisions remain separate.

## 세션 구분과 종료 조건

| 세션 | 이름 | 종료 조건 |
|---|---|---|
| 01 | CausalGround 01 — 저장소 점검·가설 신규성 검증 | 최근접 선행연구와의 차이, 좁힌 H1, 반증 조건, 최소 실험의 타당성이 문서화되고 연구자가 가설 선택에 동의한다. 중복이 발견되면 같은 세션에서 수정한다. |
| 02 | CausalGround 02 — 가설 동결·실험 설계·정답 검증 | 질문·가정·입력정보·baseline·primary metric·분할·통계·중단 기준을 동결한다. 정답 계산을 손계산 및 독립 구현으로 검증하고, 평가기/모델 입력의 분리를 확인한다. |
| 03 | CausalGround 03 — 구현·스모크 테스트 | 승인 상태를 확인한 뒤 작은 시험으로 로딩·출력 파싱·정답 채점·재실행·실제 메모리/처리량을 점검한다. 스모크 성공을 H1 지지로 해석하지 않는다. |
| 04 | CausalGround 04 — 탐색 실험·Main Finding | 독립 확증 전의 탐색 결과, 불확실성, 주요 그림, 확증할 주장을 문서화한다. 탐색 결과를 보고 바꾼 가설은 새 버전으로 기록한다. |
| 05 | CausalGround 05 — 확증 실험·통계 분석 | 미사용 평가자료에서 고정된 비교를 수행하고, 모델 간 재현·회귀·효과크기·신뢰구간·제한점을 정리한다. |
| 06 | CausalGround 06 — 논문·PPT·최종심사 | 각 주장과 결과 파일을 연결하고, 재현 점검·논문·발표 자료를 완성한다. 학회 채택이나 부정 결과의 논문화는 보장하지 않는다. |

## 일정 제약

- 2026-09-28~10-02: 아이디어 제출 및 승인 요청. 이 문서는 승인 완료를 의미하지 않는다.
- 2026-10-12: main finding과 기여점을 확보한 발표가 목표다. 따라서 핵심 탐색을 10월 13일 이후로 미루는 기존 일정은 이 목표와 맞지 않는다.
- 2026-11-09~11-20: 대부분의 실험 완료 목표.
- 2026-12-14: 최종 완료 및 심사 목표.

세션은 날짜만으로 자동 종료하지 않는다. 가설 또는 평가 타당성에 문제가 남아 있으면 완료로 표시하지 않고 일정 위험을 보고한다. 본격적인 모델 시험은 필요한 승인 이후에 수행한다.

## 각 대화의 상태 보고

응답 말미에 현재 세션, 완료 사항, 미완료 종료 조건, 다음 한 가지 행동을 명시한다. 종료 조건이 충족되면 **“세션 전환 시점입니다”**라고 알리고 다음 세션 이름과 복사할 인수인계문을 제공한다. 이것은 진행 중인 대화에서의 점검이며, 별도 자동화 없는 비동기 감시나 알림을 의미하지 않는다.

## 새 세션 시작 절차

1. `docs/STATUS.md`와 최신 인수인계문을 읽는다. 미병합 문서 PR이면 해당 브랜치를 명시적으로 읽는다.
2. GitHub의 실제 HEAD, 변경 파일, PR 상태를 확인한다. 대화 기억만으로 저장소 상태를 판단하지 않는다.
3. 이전 결정과 동결된 평가 규약을 유지한다. 변경이 필요하면 이유, 새 버전, 영향을 받는 결과를 기록한다.

## 인수인계에 반드시 포함할 내용

현재/다음 세션 이름, 저장소와 브랜치, 실제 확인한 commit, 가설 및 protocol 버전, 완료한 작업, 실제 실행한 명령과 결과 경로, 미실행 작업, 승인 및 gate 상태, 변경 금지 조건, 다음 한 가지 작업.

## 재현성과 해석 규칙

같은 SCM에서 생성한 질문·이름 변경·표현 변경은 하나의 군집으로 취급한다. 학습/개발/시험 분할은 질문 단위의 단순 무작위 분할보다 SCM/구조/템플릿 누출을 고려하여 설계한다. 동일한 문제의 조건 비교에는 짝지은 분석을 사용하고, 실제 독립 표본 단위에 맞춰 신뢰구간을 계산한다.

유의하지 않다는 결과를 효과가 없다는 증거로 바꾸지 않는다. 의미 있는 부정 결과는 사전에 정한 최소 효과에 대해 충분히 정밀한 추정, 검증된 구현, 강한 기준선, 그리고 새로운 해석을 요구한다.
