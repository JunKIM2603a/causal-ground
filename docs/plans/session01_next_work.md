## R2용 최소 설계 초안 — 승인 전 실행 금지

대상: 3~6개 변수의 작고 명시적인 SCM, 인과 질의와 자기 범위를 가진 도구 결과. 학습 없이 추론부터 설계한다.

각 기본 항목에는 다음 두 값을 따로 가진다.
- computation_correct_for_declared_query: 도구가 자신이 계산했다고 선언한 식에 맞는가?
- applicable_to_target_query: 그 결과가 현재 목표 질문을 정당하게 답하는가?

주 대비는 self-scope 계산이 정확하지만 부적용인 같은 항목에서 neutral 대 computation-verified 표시다. 정상 적용, 그래프상 동치, 이름·표현 바꿈, 숫자 우연 일치 사례를 함께 설계한다.

현재의 통제 계획:
1. 모든 조건에 같은 목표 질문·도구 자기 질문·수치·그래프·가정을 제공한다. 표지 조건만 정당한 계산 검증 정보를 노출하고, 무표지 조건도 실제 계산 상태는 동일하다.
2. 출처·모델·샘플·출력 한도를 고정하고, 표지 길이와 위치에 대한 대조를 둔다.
3. 일반 재검토, 식/타입 파서+기존 기호 검사, scope-explicit 표현을 비교한다. 실행비용이 다르면 동일 예산 비교와 비용-효용 비교를 나눠 보고한다.
4. 일반 산술·집계의 적용범위 오류 대조를 둔다. 이 대조보다 특이성이 없다면 인과 분야 최초 현상이라고 주장하지 않는다.
5. 항상 거절하는 방법은 성공이 아니다. 정상 항목 정확도와 coverage를 반드시 같이 보고한다.

탐색 규모 제안: 기본 인스턴스 200~400개, 두 모델 계열, 필요한 최소 조건. 이는 검정력 계산 결과가 아니며 최종 확증 표본 수가 아니다. 문구 변형과 반복 생성은 같은 기본 인스턴스에 속하며 독립 표본으로 세지 않는다.

## R3용 최소 설계 초안 — 승인 전 실행 금지

대상: 이진 변수·유한 잠재 반응 유형을 이용한 작은 SCM 집합. 목표는 공개 정보에 의해 점식별되지 않는 반사실 확률이다.

기본 정보 D0와 추가 정보 D1에 대해, 추가된 각 정보가 참이고 새로운 제약인지를 확인한다. 반드시 I(q;D0,A)=I(q;D0+D1,A)이며 비단일집합이어야 한다. 여기서 I는 가정 A 아래 목표 q가 가질 수 있는 값의 집합이다.

두 호환 SCM이 다른 q를 주면 비식별성의 증거가 되지만, 그것만으로 I의 전체 범위나 추가 정보 전후 동일성은 증명되지 않는다. 명시한 작은 모델 클래스에서 정확한 열거/선형계획 등 별도의 oracle 검증이 필요하다. 이 조건을 보장할 수 없으면 해당 H1의 시험을 진행하지 않는다.

기본 정보, 정확한 추가 정보, 토큰 길이 대조의 세 조건을 비교한다. 비식별 증서를 이용한 완화는 2차 탐색이며, 같은 원정보의 일반 주의 문구·구조화 방식·solver-only와 정보와 비용을 구분해 비교한다. 증서가 정답 라벨을 추가 제공하면 그것을 모델 능력 향상으로 해석하지 않는다.

점식별된 양에 대한 정답률, 비식별된 양의 부당한 점응답률, 유효한 범위·보류 비율, 파싱 실패, 비용을 분리한다. 비공개 생성 SCM의 단일 숫자를 비식별 문제의 유일한 정답으로 채점하지 않는다.

## 데이터 기록 계약 (초안)

각 항목에 scene_id, scm_family_id, graph, assumptions, target_query_ast, evidence_manifest, tool_query_ast, tool_result, computation_status, applicability_status, identification_status, oracle_method, admissible_answer_set, perturbation_id, split, generator_seed, generator_commit를 기록한다.

각 실행에는 model_id/revision, tokenizer_revision, prompt_hash, generation_config, run_seed, software_versions, hardware, raw_output, parsed_answer, parse_status, latency, token_usage를 기록한다.

정답과 상태는 도구/LLM 출력과 별도로 저장한다. 파일명이나 노출된 ID가 정답 클래스를 암시하지 않게 한다. 같은 SCM·변형·질문 가족은 분할에서 묶는다. 식별 집합의 oracle와 실제 모델 입력을 분리한다.

## 통계와 실패 판정

- 하나의 후보와 주 대비를 먼저 선택한다. exploratory/confirmatory 분할은 결과를 보기 전에 고정한다.
- 기본 SCM/scene 단위 paired 차이와 cluster bootstrap 신뢰구간을 설계한다. 변형과 반복은 독립 n이 아니다.
- 여러 후보에서 가장 큰 차이를 골라 같은 자료에서 확증했다고 주장하지 않는다. 확증은 독립 자료에서 하며 부차적 다중 비교를 표시한다.
- 최소 의미 효과(delta)와 정상 성능 손실 허용치(epsilon)는 현재 미정이다. 예비 정밀도·현실 효용을 검토하여 확증 전에 확정한다.
- p>0.05는 효과가 없다는 증거가 아니다. 무효과/등가 주장은 사전 범위와 충분한 정밀도가 필요하다.
- 오류가 없는 천장/바닥효과, 단순 baseline이 해결, 원정보/토큰 예산 통제 후 효과 소실, 직접적인 선행 중복은 규모 확대의 근거가 아니다.

## 하드웨어와 일정

사용 가능 자원: RTX 4090 24GB 두 장, RAM 128GB. 초기 선택안은 3~8B급 공개 모델의 추론 중심 비교이며 모델·정밀도·문맥 길이는 아직 미정이다. 7B BF16 가중치만의 산술량은 약 14GB이지만 KV cache와 런타임 메모리가 추가되므로 실제 batch는 smoke로 확인해야 한다. 두 GPU를 단일 48GB 메모리처럼 간주하지 않는다. 가능하면 모델/조건을 GPU별 독립 작업으로 나눈다.

10/2 아이디어 제출과 10/12 main finding 일정은 유지하되, 날짜를 맞추려고 신규성을 PASS 처리하지 않는다. 사전 승인과 후보 선택 후 작게 탐색하는 계획이며, 완료 시간이나 성능을 보장하지 않는다.
